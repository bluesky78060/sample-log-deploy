HIGH✅ 검증됨 setWindowOpenHandler 부재 — 임의 새 창/외부 네비게이션 미차단

src/index.ts에 setWindowOpenHandler 0건, will-navigate만 2건. will-navigate는 같은 창 이동만 막고 window.open()/target=_blank 새 창 생성은 못 막음 → XSS·악성 링크가 임의 URL을 새 창에 로드.

조치 → setWindowOpenHandler(()=>({action:'deny'})) + 외부 링크는 shell.openExternal · web-contents-created에도 적용
HIGH✅ 검증됨 HTML meta CSP가 unsafe-eval + unsafe-inline 허용

프로덕션은 loadFile(docsPath)로 약한 meta CSP 문서를 로드. 헤더 CSP는 강하나 meta가 약화시킴. 사용자 입력(시료/생산자) 렌더링에 직접 innerHTML= 다수(189곳 중 일부 DOMPurify 미경유).

근거: src/index.html:8 · docs/index.html:8 · src/water/water-script.ts:2483

조치 → meta CSP에서 unsafe-eval 제거(nonce/hash) · 직접 innerHTML을 setInnerHTML(sanitize 래퍼)/textContent로 일원화
HIGH✅ 검증됨 firestore.rules 부재 — 서버측 인가 미확인

리포에 firestore.rules/firebase.json 없음. Firebase 클라이언트 config는 공개이므로 규칙이 없거나 공개면 누구나 시료/생산자 PII 읽기·쓰기 가능.

조치 → 인증 필수 규칙을 리포에 두고 배포(IaC). 콘솔에 이미 있어도 회귀 방지 위해 코드화

✅잘 된 점 — 그대로 유지

  • 메인 프로세스 path traversal 방어가 모범적 — validateFilePath가 realpath·화이트리스트·null byte·URL 인코딩 다중 검증, write/read 핸들러에 실제 적용
