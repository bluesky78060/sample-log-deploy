# SAMPL-2-29 플랜 리뷰

## ⚠️ 플랜 리뷰를 수행하지 않았다 (정직한 기록)

`critic` 에이전트 플랜 리뷰를 **실행하지 않았다.** 하지 않은 검증을 했다고 기록하지 않는다.

**사유**: 사용자 지시 — "코드 수정이나 중요가 낮은 작업은 플랜리뷰하지말고 진행해줘" (이 세션). 이 티켓은 `.gitignore` 8줄 + 인덱스 추적 해제이며 **런타임 코드·동작 변경이 없다.**

## 생략을 정당화하는 근거

| 근거 | 내용 |
| --- | --- |
| 런타임 영향 0 | `.gitignore`와 git 인덱스만 바꾼다. 빌드 산출물·번들·앱 동작에 영향이 없다 |
| 되돌리기 비용 0 | 파일은 디스크에 남고 인덱스에서만 빠진다. `.gitignore` 되돌리고 `git add`하면 원복된다 |
| 검증이 기계적 | `git check-ignore -v`가 각 규칙을 실측한다. 판단이 아니라 확인이다 |
| 선례 존재 | 메인 프로젝트가 이미 `docs/assets/`를 같은 이유로 ignore한다 (`.gitignore:106`) |

## 그래도 남는 리스크와 대응

1. **negation 함정** — git은 상위 디렉터리가 ignore되면 `!` 예외가 동작하지 않는 경우가 있다. `.omc/`를 ignore하면서 `!.omc/skills/`를 되살리려는 것이 정확히 그 패턴이다.
   → 플랜 4단계에서 `git check-ignore .omc/skills/foo`로 **실측**한다. 걸리면 규칙을 `.omc/*` 형태로 바꿔 재검증한다.

2. **다른 클론에서의 삭제** — `git rm --cached` 커밋을 pull하면 그 파일이 로컬에서 사라진다.
   → 산출물이라 무해하다. 커밋 메시지에 명시해 놀라지 않게 한다.

3. **원본까지 잃는 실수** — `docs/manual/images/`를 ignore하면서 원본 `src/manual/images/`를 건드리는 것.
   → 플랜 "하지 않을 것"에 명시. 원본이 추적 중임을 확인하고 손대지 않는다.

## 코드 리뷰는 생략하지 않는다
구현 후 `code-reviewer` 리뷰는 정상 수행한다. 생략한 것은 **플랜** 리뷰뿐이다.
